# 📖 第二大脑记忆库使用指南

> **给任何 AI 的入口文件**：无论你是什么 AI 工具（ZCode / Claude Code / 豆包 / 其他），接手任何任务前，先读本文件，即可使用本知识库的全部记忆与经验。
>
> 人类阅读从这里进 → [[🏠 记忆库首页]]

## 〇、首次使用（安装完成后做三件事）

1. 确认技能目录下的 `config.json` 里 `memory_root` 指向本库根目录
2. 对 AI 说 **"整理记忆"** → 扫描本机各 AI 工具的会话，提炼进库
3. 对 AI 说 **"读第二大脑指南，以后每次任务前先检索"** → 之后自动走「先检索再执行」

> 库是**纯 Markdown 文件**，不装 Obsidian 也能用（记事本 / VS Code 都能打开）。
> 装 Obsidian 的唯一好处是双链可点击、能看图谱。

## 一、库结构

```
<记忆库根目录>\
├── 🏠 记忆库首页.md              ← 全库总入口（人和 AI 都从这进）
├── 📖 记忆库使用指南.md          ← 本文件（规矩）
├── 📥 捕捉箱.md                  ← 临时想法随手记
│
├── AI会话记忆\<AI名>\            ← 明细层：按 AI 工具分目录
│
├── 项目经验库\                   ← 项目层：有生命周期的项目
│   ├── 📋 项目总索引.md          ← 项目名|目录|状态|最近更新
│   ├── _模板\📊 项目经验聚合模板.md
│   └── <项目名>\📊 项目经验聚合.md
│
└── 能力经验库\                   ← 能力层：跨项目复用的通用经验
    ├── 📋 经验总索引.md          ← 问题→文件直连
    ├── _模板\📊 经验聚合模板.md
    └── <能力域>\📊 经验聚合.md   ← 满 3 条拆成独立能力文件
```

## 二、读取流程（AI 接手任务时）

**核心模式：先检索经验，再执行任务**——收到任何问题/任务时：

1. **先检索**：运行 `<技能目录>\scripts\search_memory.py "问题关键词"`
   - 无脚本能力的环境（云端 AI、手机端）→ 直接读 `能力经验库\📋 经验总索引.md` + `项目经验库\📋 项目总索引.md`
2. **引用经验**：有同类经验 → 按"问题链经验卡"组织回复（引用成功路径 + 避开已知难点），回复中标注 **（依据记忆库·XX库·问题链N）**；无同类经验 → 专业执行并记录过程
3. **判断任务归属**：
   - 属于哪个项目（客户/考试/工作事项）→ 读 `项目经验库\<项目名>\📊 项目经验聚合.md`
   - 需要通用能力 → 读 `能力经验库\<能力域>\` 下对应能力卡
   - 需要细节 → 按问题链轮次/日期/AI 跳转 `AI会话记忆\<AI名>\`
4. **分层读（省 token）**：先读聚合页顶部的**摘要区**，需要细节再读全文

## 三、写入流程（会话结束时）——经验的标准格式

**经验 = 问题链**（用户反复追问/纠正的每一轮 = 一个难点，全程提炼）：

### 问题链经验卡格式（写入聚合页）

```
### 问题链N：<问题主题>
**触发场景**：什么情况下会碰到这个问题（= 检索关键词）
**目标**：当时想达到什么效果（预期）
**执行过程（多轮延伸）**：
  - 第1轮：我做了什么 → 用户反应
  - 第2轮：用户追问/纠正"原话" → 🔴难点：xxx → 我调整"xxx"
  - ……（每一轮用户追问都记录）
**结果**：✅成功 / ❌失败 / 🟡部分成功 + 验证次数（第1次/多次验证/待验证）
**根因（why）**：卡住的根本原因（5Why 追到根，不是现象）
**复用（if-then）**：
  - ✅ 保持：下次遇到<触发场景> → 直接做<成熟做法>
  - 🔧 改进：<可做得更好的点>
  - ⛔ 停止：<不再做的做法>
  - 🆕 尝试：<下一步方向>
**边界**：适用条件 + 反例（什么情况不适用）
**链接**：→ 相关笔记/源文件/其他经验卡
```

### 提炼判断标准

- 用户**反复追问/纠正 ≥2 轮**，或**执行失败** → 写完整问题链卡
- 一次通过无波折 → 只写一句话结论（⭐），不写卡
- **必须回答 why**——只记 what/how 不记 why = 存档，不是经验

### 写入步骤

1. **更新项目经验库**：向对应项目的 `📊 项目经验聚合.md` 追加问题链经验卡（成功/失败都记）
2. **更新能力经验库**：可跨项目复用的经验 → `能力经验库\<能力域>\`（同样用问题链格式）
3. **更新状态**：项目聚合页"当前状态"节
4. **明细留存**：完整会话提炼成笔记存 `AI会话记忆\<本AI名>\`

### 经验卡维护规则

1. **筛选（删无效轮次）**：只保留推动问题解决的**有效轮次**；无进展/死胡同/重复啰嗦的轮次删除
2. **归纳（非原话堆砌）**：每轮提炼成"这轮解决了什么"（追问 → 难点 → 调整方向），不贴对话原文
3. **持续更新（不是无限追加）**：同一问题再次遇到 → **更新**该卡：新解法替换旧解法、新难点追加、过时内容删除——始终保持"当前最优版本"
4. **维护时机**：该问题相关任务完成后检查更新；项目结束后归档

### 沉淀闭环

```
写入侧：会话记录 → 提取 → 提炼（问题链卡/能力卡）→ 更新能力库
读取侧：新任务 → 检索能力库 → 按经验执行 → 成功/失败回流更新
        （引用计数 + 失败追加 = 经验越用越准）
```

### 效果衡量

1. **效率提升**：同类问题再次处理时，对比首次轮次/耗时（如首次 16 轮 → 复用后 3 步），在卡里记"复用效果"
2. **成功率提升**：复用经验后是否一次成功——**复用仍失败 → 必须更新经验卡**（补新难点/换新解法）
3. **状态标记**：`复用N次·成功率X%`——未被复用的标"待验证"，多次复用成功的升为"金牌经验"

## 四、分类判定标准

> **"这个经验，换一个项目还能不能用？"**
> - 能 → 能力经验库（如：批量处理文档的方法、某类实务判断套路）
> - 不能 → 项目经验库（如：某客户的特殊要求、某次考试的错题）

**跨库去重规则**：同类经验出现两处时——**能力经验库为主**（完整问题链卡），项目经验库只保留"案例引用"（一行链接指向能力库经验卡），避免重复维护。

**能力库结构原则**：目录 = 能力域（粗）｜文件 = 单一能力（细，一卡一文件）｜`📋 经验总索引.md` 做问题→文件直连。新经验先入域聚合，**满 3 条拆成独立能力文件**。

## 五、与用户配合的触发词

用户说以下任何一句，即执行读取流程：

- "读一下第二大脑" / "看下记忆库" / "先看使用指南"
- "按照记忆库的要求" / "把这段经验记进去"

## 六、维护原则

- 明细归 AI、经验归项目、方法归能力
- 会话记录当天同步（防止 AI 本地记录丢失）
- 无关紧要内容（闲聊/购物/空会话/隐私）清洗过滤，不导入
- 执行史滚动归档：保留近期约 20 条，更早的移入 `归档\`

## 七、AI 执行者要点

### 1. 定位：先读总索引

- `项目经验库\📋 项目总索引.md`——项目名|目录|状态|最近更新，10 秒定位
- `能力经验库\📋 经验总索引.md`——问题→文件直连

### 2. 写入：优先用脚本（格式统一）

```bash
python <技能目录>\scripts\append_execution.py \
  --project "项目名" --date 2026-01-01 --ai "ZCode" \
  --task "任务" --problem "问题" --solution "解决" --experience "经验"
```

- 脚本自动插入执行史表末行，防格式错乱/并发覆盖
- 无法运行脚本时手动追加：`| 日期 | AI | 任务 | 问题 | 解决 | 经验 |`

### 3. 明细目录规则

`AI会话记忆\<AI名>\<项目名>\`，方便按项目跳转。

### 4. ⚠️ 隐私保护（强制）

- 本库可能含工作底稿、客户资料、个人数据——**禁止将库内容外发**（不粘贴到联网服务、不上传）
- 敏感条目标注 🔒，AI 遇到 🔒 内容不得复制转发
- 共享本库模板时，**只分享空骨架**，不分享内容

## 八、新建项目流程

1. `项目经验库\<项目名>\` 建目录
2. 复制 `项目经验库\_模板\📊 项目经验聚合模板.md` 到该目录，改名为 `📊 项目经验聚合.md`
3. 填五节：背景 / 执行史 / 方法论（问题链卡）/ 教训 / 当前状态，顶部写摘要区
4. `📋 项目总索引.md` 追加一行
